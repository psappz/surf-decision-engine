# PR #4 implementation review

Spot Intelligence now consumes exactly one completed immutable Consensus run and snapshots only output-relevant `SurfSpot` rule fields. Canonical SHA-256 hashes cover every behavioral global setting and the exact sorted rule rows, including spot IDs, invalid raw audit values, effective fallbacks, and metadata issues. Display/private/unrelated fields are excluded.

Repository lifecycle guards creation as running, point insertion into an existing running run, and one terminal running-to-completed/failed transition. Service transactions prevent partial points and preserve exact required provenance within a hard envelope. Idempotency reuses equivalent completed calculations by consensus run, rule hash, engine/config hashes, and canonical selected-point scope. Failed retries and forced calculations create distinct immutable attempt records. Migration `0007` replaces the old input-only uniqueness constraint with an input-plus-scope-plus-sequence constraint and adds the missing nonnegative maximum check. Database uniqueness plus bounded retry handles ordinary allocation races; sustained contention remains an explicit retryable operational risk. Downgrade is data-dependent after forced/failed retries or multiple scopes because the older schema cannot represent them without collisions.

Factor outputs are independently reviewable and do not include a total score or recommendation semantics. The breaking transform is explicitly provisional/model-derived. Current runtime scoring, recommendation, provider, UI, template/static, and scheduler read paths are untouched.
